# where-were-we

[English](README.md) · [한국어](README.ko.md)

계속 바뀌는 서비스의 코드를 사람과 AI 에이전트가 함께 따라가는 구조 지도입니다.

프로그램·화면·서버 요청·데이터가 어떻게 이어지는지, GitHub에서 진행 중인 작업이 어디서 겹치는지 봅니다. 에이전트도 MCP로 같은 지도를 읽고 계획과 수정에 참고합니다.

![전체 구조에서 렌더 취소와 공유 데이터까지 따라가는 Lumen Studio 데모](docs/images/ko/demo.gif)

화면은 가상 콘텐츠 제작 플랫폼 **Lumen Studio**를 예시로 촬영했습니다. 지도·GitHub 작업·AI 설명·버전 정보는 예시 데이터이며, UI는 실제 앱입니다.

## 설치

Apple Silicon Mac, macOS 11 이상, [Homebrew](https://brew.sh/)가 필요합니다. [릴리즈](https://github.com/ganggangstone/where-were-we/releases/latest)에서 ZIP을 직접 받을 수도 있습니다.

```sh
brew install --cask ganggangstone/tap/where-were-we
gh auth login
```

Python은 앱에 포함되어 있습니다. Homebrew는 git과 GitHub CLI를 함께 설치합니다. 상세 분석·화면 묶음·전체 구조·프로그램 작업·요청 단계는 도구 호출을 지원하는 MCP 에이전트로 만들며 Claude Code 설치가 필요하지 않습니다. MCP 서버의 PATH에서 git·gh를 찾을 수 있어야 합니다.

**첫 배포 파일에는 코드 서명과 공증이 없습니다.** macOS가 처음 실행을 막을 수 있습니다. Apple의 [확인되지 않은 개발자의 앱 열기 안내](https://support.apple.com/ko-kr/guide/mac-help/mh40616/mac)를 참고하세요.

### 첫 지도 만들기

상단 **＋**를 누르고 서비스 이름과 코드가 들어 있는 폴더를 입력하세요. 표시 이름을 비우면 폴더 이름을 쓰며 내부 식별자는 자동으로 만듭니다. **코드 연결**에서 같은 서비스의 다른 코드 폴더를 추가하세요. **모든 코드**로 함께 보고 **새로고침**을 눌러 지도 데이터를 가져옵니다.

새 연결은 폴더에서 현재 선택된 브랜치에 저장된 코드(`HEAD`)를 분석합니다. 다른 버전을 보려면 **분석할 코드 버전**을 펼쳐 브랜치·태그·커밋을 지정하세요. 비교할 기준 버전은 비워 두어도 되며, 기존 연결의 버전 설정은 유지합니다. React Router 웹과 FastAPI 서버가 서로 다른 레포에 있어도 수집합니다. `frontend/src` 또는 `src`, `backend/app` 또는 `app`을 자동으로 찾으며, 다른 소스 폴더는 설정에서 지정합니다. 다른 언어·프레임워크는 먼저 새로고침한 뒤 레포를 선택하고 **코드 분석 요청**을 누르세요. 분석 요청을 복사해 MCP가 연결된 에이전트에 전달하세요. 해당 에이전트가 자신의 모델로 선택한 브랜치의 코드를 MCP로 조회하고 상세 지도와 요청 처리 단계를 제출합니다. 기존 요청 창에서 **요청 복사 → 에이전트에 전달 → 저장된 결과 확인** 순서로 진행하세요. 에이전트가 결과를 저장한 뒤 **저장된 결과 확인**을 누르면 PR을 다시 수집하지 않고 분석만 읽습니다. **바뀐 것**과 비교 기준은 유지합니다. 복사만으로 분석이 시작되지는 않으며, 결과 없음·이전 결과·다른 버전·일부 저장·새 결과 저장을 구분해 보여 줍니다. 앱은 결과를 검증·저장하며 다른 모델을 대신 실행하거나 AI 사용료를 제공하지 않습니다. 원문 일치는 근거 확인이며 AI 해석의 정확성을 보장하지는 않습니다. 일반 새로고침에서는 AI를 호출하지 않고, 코드가 바뀌면 이전 AI 지도를 보존하면서 재분석이 필요하다고 표시합니다. **설정**에서 앱을 열 때 새로고침할지, 지난 새로고침·레포별 내 마지막 커밋·지정한 시각 중 언제부터 변경 내역을 볼지 고를 수 있습니다. 기준을 저장한 뒤 새로고침하면 반영됩니다. 지정한 날짜·시각은 설정에서 직접 바꾸기 전까지 새로고침해도 유지됩니다.

**서버 연결과 코드 위치 직접 지정**을 펼치면 요청을 받는 서버 코드를 이름으로 선택할 수 있습니다. 일치하는 요청은 사용자가 지정한 연결로 표시합니다. 대상이 지정되지 않았거나 여러 곳이 일치하면 후보로 남습니다. 테이블 이름이 같아도 기본적으로 별개이며, 공유 데이터는 명시적으로 지정해야 합니다. **코드 연결 → 여러 코드가 같은 데이터를 사용할 때**에서 코드와 테이블을 연결하세요. 내부 식별자는 자동으로 만듭니다. 연결 수정과 제거도 같은 화면에서 할 수 있으며 수집한 테이블 이름을 선택지로 보여 줍니다. 수집에 실패한 레포는 마지막 성공 지도를 유지하고 기준 커밋·마지막 성공 시각 옆에 실패를 표시합니다.

github.com 코드는 연결할 때 사용하는 GitHub 계정을 기억합니다. 기존 프로젝트는 첫 새로고침 때 기억합니다. 다른 작업에서 로그인 계정을 바꿔도 이 연결은 유지됩니다. 수집에 실패하면 **GitHub 계정 바꾸기**에서 로그인된 계정을 선택하고 다시 수집할 수 있습니다. 인증 정보는 GitHub CLI에서 가져오며 앱 설정에는 계정 이름만 저장합니다. HTTPS로 코드를 가져올 때는 기억한 계정을 쓰고, SSH 연결은 기존 SSH 키를 씁니다.

기존 프로젝트도 그대로 열립니다. **코드 연결**에서 기존 레포를 유지하며 다른 레포를 추가할 수 있고, 이전 지도 파일은 옮기거나 지우지 않습니다.

앱은 한국어로 시작합니다. 상단 **English**로 바꾸면 선택을 이 기기에 저장합니다. 프로젝트 이름·코드·AI 설명은 원문을 유지합니다.

### 바뀐 것

새로 생기거나 사라진 화면·요청·이동 경로, 병합 PR과 바뀐 AI 근거를 봅니다. 새로고침으로 PR·이슈 근거를 보존한 뒤 **변경 설명 요청**을 에이전트에 전달하고 **저장된 결과 확인**을 누르세요. 문제별 카드에서 바꾼 이유·전후 동작·해결 방법·데이터 영향·중단과 복구·용어·모르는 부분을 인용과 원본 링크로 봅니다. 같은 문제의 PR은 묶고 한 PR이 여러 문제를 고쳤으면 나눕니다. 고유 PR 수는 카드 수와 별개로 셉니다. ## 에이전트와 함께 쓰기

**에이전트 연결**을 누르고 안내를 복사해 Claude Code·Codex 등 MCP를 지원하는 에이전트에 전달합니다. 에이전트는 설정을 바꾸기 전에 허락을 구합니다.

계획 전에는 `changes`, 수정 전에는 `impact`를 확인하도록 요청하세요. 에이전트가 같은 지도로 영향받는 곳과 겹치는 작업을 확인할 수 있습니다. MCP 도구의 `repository`에 레포 ID를 넣으면 범위를 좁힙니다. 여러 레포가 있는 프로젝트에서 테스트 규칙을 저장하려면 대상 레포를 지정해야 합니다.

## 업데이트

앱을 열 때 하루에 최대 한 번 새 버전을 확인합니다. **버전·업데이트**에서 릴리즈 노트를 읽거나 직접 확인하고, 자동 확인을 끌 수 있습니다.

Homebrew로 설치했다면 **지금 업데이트**를 누르세요. 새 버전이 Homebrew에 올라왔는지 확인한 뒤 앱이 닫히고, 설치가 끝나면 자동으로 다시 열립니다. 수집이나 AI 작업은 끝낸 뒤 업데이트하세요. 설치나 재실행에 실패하면 이전 앱 복구를 시도하고 오류를 보여 줍니다. 복구까지 실패하면 복구용 파일을 남깁니다. 지도는 유지합니다.

업데이트 중 맥이 꺼지거나 강제 종료되면 `~/.where-were-we/.app-update.log`와 `.app-update.json`에 복구 안내가 남습니다. 터미널에서 `open -a TextEdit ~/.where-were-we/.app-update.log`로 로그를 열면 보관한 앱 사본과 원래 위치를 확인할 수 있습니다. Finder에서 사본을 원래 위치로 복사하고 대치를 선택하거나, 로그에 적힌 Homebrew 재설치 명령을 실행하세요.

```sh
brew update && brew upgrade --cask ganggangstone/tap/where-were-we
```

위 명령은 직접 업데이트할 때 사용합니다. 명령 복사만 제공하는 이전 버전에서도 이 방법으로 업데이트할 수 있습니다. ZIP으로 설치한 앱은 업데이트 버튼으로 관리하지 않습니다. 앱을 제거해도 지도는 남습니다.

## 데이터와 한계

- 지도는 `~/.where-were-we/`에 둡니다. 프로젝트 구조가 들어 있으므로 공개 저장소에 넣지 마세요.
- 수집 도구는 `git fetch`를 실행하고 로컬 파일·git 이력·GitHub 작업·작업 폴더를 읽습니다. 다른 브랜치로 이동하거나 대상 저장소의 파일을 수정하지 않습니다.
- 상세 분석은 연결된 MCP 에이전트와 해당 계정을 사용합니다. `analyze`가 분석 안내와 schema를 제공하고, `analysis_source`로 고정 커밋을 읽으며, `record_analysis`가 결과를 검증·저장합니다. 상세 지도 저장 뒤에는 같은 분석 요청에서 전체 구조와 프로그램별 하는 일도 함께 분석·저장합니다(`request_ai_task`·`record_ai_task`). 앱에서 프로그램을 누르면 저장된 하는 일을 바로 보여 주며, 결과가 없으면 아직 분석되지 않았다고 표시합니다. 묶음·요청 단계 분석도 같은 연결 에이전트를 사용합니다. 요청을 복사해 에이전트에 전달하고, 저장이 끝나면 **저장된 결과 확인**을 누르세요. 변경 내역을 갱신하지 않고 분석만 읽습니다. 소스 처리·전송은 선택한 에이전트와 제공자 설정을 따릅니다.
- 자동 코드 추출은 React Router·axios, FastAPI, SQLAlchemy를 지원합니다. 다른 언어·프레임워크는 연결된 에이전트에 코드 분석을 요청할 수 있습니다. AI가 확인하는 범위에 따라 결과가 달라지며 전체 코드를 빠짐없이 분석한다고 보장하지 않습니다. AI 분석 표시, 원문 검사, 확인하지 못한 부분과 코드 변경 후 재분석 안내를 함께 보여 줍니다. 소스 폴더는 레포마다 지정할 수 있습니다. 수집 성공과 분석 범위를 따로 표시하며 기본 수집에서 확인하지 못한 부분과 분석 대상에서 제외한 부분을 구분합니다. React Router→FastAPI→SQLAlchemy 테이블 연결과 Vue→Go→테이블 연결을 가상 코드로 검사합니다. Vue·Go 검사는 준비한 AI 응답 JSON을 사용하며, 근거 검사와 지도 연결을 검증한 결과입니다. 실제 모델의 분석 정확도를 측정한 것은 아닙니다.
- `dev`와 `main`은 코드 브랜치 비교입니다. 실제 배포 상태를 확인하는 것은 아닙니다. git에 없는 프로그램과 실행 상태는 실제 환경을 확인하기 전까지 미확인으로 남습니다.
- 읽기·변경은 GET과 나머지 HTTP 방식으로 구분합니다. 테스트나 이동 경로를 잇지 못한 것은 추출기가 그 모양을 인식하지 못해서일 수도 있습니다. AI 설명과 후보 연결은 확인이 필요하며, 코드 인용문이 일치해도 설명의 정확성이 보장되지는 않습니다.
